# 07 · 确认交互卡片化（feishu_ask_user_question）

> 适用范围：admin / sale / finance 三端技能中所有采用 `need_confirm` 二次确认机制的工具（登录、登出、创建、更新、删除等写操作）。
> 目标：把「Agent 用文字问用户『确认吗？』」升级为「发飞书选项卡片，用户点选确认/取消」，交互更直观、更不易误操作。

---

## 7.1 调用模板：feishu_ask_user_question 完整 JSON 参数

**工具名**：`feishu_ask_user_question`（飞书官方提问卡片工具，仅飞书渠道可用）

**参数结构**：`questions` 数组，每项一个提问卡片问题，最多 6 个。

```json
{
  "questions": [
    {
      "question": "确认退出当前账号吗？",
      "header": "退出确认",
      "options": [
        { "label": "确认退出", "description": "将调用后端登出接口并清除本地凭证" },
        { "label": "取消", "description": "保持当前登录状态" }
      ],
      "multiSelect": false
    }
  ]
}
```

### 关键参数约定

| 参数 | 类型 | 必填 | 约定 |
|:-----|:-----|:----:|:-----|
| `question` | string | ✅ | 提问正文，含具体操作对象与影响（如「确认删除角色 #3？」） |
| `header` | string | ✅ | 短标签，**≤12 字符**（超长会被截断） |
| `options` | array | ✅ | 选项列表，每项 `{label, description}`；`description` 解释该选项后果 |
| `multiSelect` | boolean | ✅ | 确认场景**固定 false**（单选）；仅多选录入场景才为 true |

### 选项与 confirmed 的映射约定

| 用户点选 | Agent 解析 | confirmed |
|:---------|:-----------|:---------:|
| 第一个选项（确认/是/执行） | 确认 | `true` |
| 第二个选项（取消/否） | 取消 | `false`（不再调用执行） |

> ⚠️ 选项顺序固定：**第一项 = 确认执行，第二项 = 取消**。Agent 收到答案后必须按此约定解析。

---

## 7.2 Agent 处理逻辑：收到答案 → 解析确认/取消

### 逻辑总览

```
技能返回 action=need_confirm（含确认摘要）
   ↓
Agent 调 feishu_ask_user_question 发选项卡片
   ↓
用户点选 → 答案以消息形式回传 Agent
   ↓
Agent 解析：确认 → 以 confirmed=True 调技能执行
           取消 → 以 confirmed=False 调技能（或直接回复"已取消"）
   ↓
技能执行 → 返回结果 → Agent 美化输出
```

### 示例 A：退出登录（tenant_logout / sale_logout）

**Step 1 — 技能返回 need_confirm：**

```python
# 用户发起登出，Agent 调 tenant_logout()（confirmed 默认 False）
result = tenant_logout()
# → { "action": "need_confirm", "title": "退出登录", "summary": ["确认退出当前账号？"], ... }
```

**Step 2 — Agent 发选项卡片：**

```json
{
  "questions": [
    {
      "question": "确认退出当前登录账号吗？",
      "header": "退出确认",
      "options": [
        { "label": "确认退出", "description": "登出并清除本地凭证" },
        { "label": "取消", "description": "保持登录状态" }
      ],
      "multiSelect": false
    }
  ]
}
```

**Step 3 — 用户点选「确认退出」，Agent 解析后执行：**

```python
# 收到答案=确认
result = tenant_logout(confirmed=True)
# → 真正调用后端登出接口，清除凭证，输出退出提示
```

**Step 4 — 用户点选「取消」，Agent 处理：**

```python
# 收到答案=取消 → 不再调用执行，直接告知
# 输出："已取消退出，保持当前登录状态。"
```

### 示例 B：创建楼盘（sale_project_create）

**Step 1 — 技能返回 need_confirm：**

```python
result = sale_project_create(
    project_code="P2026001", project_name="翡翠湾", developer="XX地产",
    confirmed=False,  # 未确认 → 返回确认摘要
)
# → { "action": "need_confirm", "summary": ["楼盘编码: P2026001", "楼盘名称: 翡翠湾", ...] }
```

**Step 2 — Agent 发选项卡片（展示摘要 + 确认）：**

```json
{
  "questions": [
    {
      "question": "确认创建楼盘【翡翠湾】(P2026001)？",
      "header": "创建确认",
      "options": [
        { "label": "确认创建", "description": "调用后端创建楼盘" },
        { "label": "取消", "description": "不创建" }
      ],
      "multiSelect": false
    }
  ]
}
```

**Step 3 — 用户点「确认创建」，Agent 执行：**

```python
result = sale_project_create(
    project_code="P2026001", project_name="翡翠湾", developer="XX地产",
    confirmed=True,  # 确认后执行
)
# → 后端真正创建 → 返回楼盘ID与详情
```

**Step 4 — 用户点「取消」→ Agent 直接回复"已取消创建"**，不再调用执行。

## 7.3 标准流程：完整闭环

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 用户发起操作（"退出登录" / "创建楼盘" / "删除角色" ...）     │
│                                                             │
│ 2. Agent 调技能（confirmed=False 或缺省）                    │
│    → 技能返回 { action: "need_confirm", summary: [...] }     │
│                                                             │
│ 3. Agent 调 feishu_ask_user_question 发选项卡片              │
│    → 卡片含确认摘要 + 两个选项（确认执行 / 取消）              │
│                                                             │
│ 4. 用户点选 → 答案回传 Agent（新消息）                        │
│                                                             │
│ 5. Agent 解析：                                              │
│    ├─ 确认 → 调技能(confirmed=True) → 执行 → 美化输出         │
│    └─ 取消 → 直接回复"已取消"，不调执行                       │
│                                                             │
│ 6. 技能执行结果 → Agent 用 Markdown/OpenUI 卡片输出            │
└─────────────────────────────────────────────────────────────┘
```

**关键约定**：
- `need_confirm` 的返回**永远不直接执行**，必须等用户确认。
- 技能（tenant_*/sale_*）的 `confirmed` 参数与机制**保持不变**，仅确认交互方式从「文字」换成「选项卡片」。
- 取消时不带任何副作用（不调后端、不改凭证、不改数据）。

## 7.4 使用要点（5 条）

1. **必须用官方工具**：确认卡片只能用 `feishu_ask_user_question` 发送，禁止手写 JSON 卡片或伪造回调。工具返回后立即结束，答案会以新消息回传，**不要轮询、不要重复调用**。

2. **两个选项足够**：确认场景固定 2 个选项（确认执行 / 取消），不要加第三个。更多选项只用于真正的枚举选择（如"查看哪类业绩"），且此时同样用官方工具。

3. **敏感字段脱敏**：`need_confirm` 摘要中的密码、token 等敏感字段必须脱敏（如 `密码: ********`）再放进 `question`/`summary`，禁止明文回显。卡片回调同样不承载明文密码。

4. **保持技能 confirmed 机制不变**：`tenant_*` / `sale_*` 的 `confirmed=False → need_confirm → confirmed=True → 执行` 三段式**保持原样**，本规范只替换「确认交互」这一环的实现（文字 → 卡片点选），不改技能内部逻辑。

5. **适用技能清单**：
   - admin：`tenant_login`（确认登录）、`tenant_logout`（确认登出）、`tenant_create_user`、`tenant_update_user`、`tenant_delete_user`、`tenant_update_role`、`tenant_delete_role`
   - sale：`sale_login`（确认登录）、`sale_logout`（确认登出）、`sale_project_create/update/delete`、`sale_customer_create/update/delete/transfer`、`sale_house_control`（停售/恢复等）、`sale_channel_terminate`、`sale_broker_update`、`sale_team_dissolve`、`sale_bill_audit/freeze` 等所有带 `confirmed` 参数的写操作
   - finance：`finance_*` 中带 `confirmed` 参数的写操作
   - 原则：**凡技能返回 `need_confirm` 的，一律走本规范**。

---

## 备注

- 本规范依赖 `feishu_ask_user_question` 工具在**飞书渠道**可用（该工具需飞书消息上下文，WebChat 等非飞书渠道不可用）。
- 若目标渠道不是飞书，Agent 应**降级为文字二次确认**（沿用原 `need_confirm` 交互），不影响技能可用性。
